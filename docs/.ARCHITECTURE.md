# Fluxis EOD: Technology Stack & Architecture Specification

## 1. Project Overview

**Project:** Fluxis  
**Type:** Electronic Document Management System (EOD)  
**Architecture:** Modular Monolith, REST API, SPA  
**Deployment:** Docker Compose on Linux VPS  
**Primary language:** TypeScript

Fluxis is a web-based document management system designed for uploading, organizing, reviewing, approving, and archiving documents.

The application should support role-based access control (RBAC), document workflows, OCR processing, user administration, audit logs, and integration with external identity providers such as Active Directory through LDAPS.

The architecture should prioritize maintainability, modularity, security, and efficient resource utilization.

## 5. Database

Use PostgreSQL with Prisma ORM.

Initial entities should include:

- User
- Role
- Permission
- UserRole
- RolePermission
- Document
- DocumentVersion
- DocumentStatus
- DocumentType
- DocumentWorkflow
- WorkflowStep
- ApprovalDecision
- OcrJob
- AuditLog
- IntegrationConfiguration

Use UUID identifiers where appropriate.

Store document metadata in PostgreSQL. Store uploaded files in a dedicated storage volume rather than storing entire binary files directly in database records.

Implement appropriate foreign keys, indexes, uniqueness constraints, timestamps and referential integrity.

## 6. OCR and Background Jobs

Use Tesseract OCR with BullMQ and Redis.

OCR processing must be asynchronous.

Suggested workflow:

1. User uploads a document.
2. Backend validates the file and permissions.
3. Document metadata is stored in PostgreSQL.
4. File is saved in private storage.
5. OCR job is created and queued.
6. Background worker processes the document using Tesseract.
7. Extracted text and processing status are saved.
8. Frontend retrieves updated OCR status through the REST API.

Support job states:

- Pending
- Processing
- Completed
- Failed

Implement retries, error handling, file size limits and OCR execution timeouts.

Initially support PDF, PNG and JPEG. PDF processing may require conversion or text extraction before invoking Tesseract.

## 7. Authentication and Authorization

Use secure session or token-based authentication.

Requirements:

- Password hashing using Argon2id
- Secure authentication endpoints
- Role-based access control
- Backend permission checks
- Protected frontend routes
- Session expiration handling
- Audit logging for sensitive actions
- Optional future LDAPS integration

Prefer HttpOnly, Secure cookies where applicable. Do not store sensitive authentication tokens in localStorage.

The frontend must not be considered an authorization boundary.

## 8. Infrastructure and Deployment

Target environment: Linux VPS.

Use Docker Compose.

Suggested services:

```text
fluxis/
├── frontend/
├── backend/
├── infrastructure/
│   ├── docker/
│   ├── nginx/
│   └── scripts/
├── compose.yaml
├── .env.example
├── README.md
└── DEFINITION_OF_DONE.md
```

Container services:

- Reverse proxy
- Frontend
- NestJS backend
- PostgreSQL
- Redis
- OCR worker

Use internal Docker networks. Expose only necessary HTTP/HTTPS ports publicly.

PostgreSQL and Redis must not be exposed directly to the internet.

Use persistent volumes for PostgreSQL and document storage.

Provide health checks, restart policies, environment-based configuration and a documented backup/restore procedure.

Optimize resource usage for a small VPS. Limit OCR worker concurrency.

## 11. Instructions for Codex

Before implementing a feature:

1. Inspect the existing repository and project structure.
2. Reuse existing components and conventions.
3. Follow the selected architecture and technology stack.
4. Do not introduce alternative UI frameworks or backend frameworks without justification.
5. Prefer small, maintainable and testable changes.
6. Keep frontend and backend responsibilities separate.
7. Update documentation when architecture or configuration changes.
8. Run relevant lint, type-check, build and test commands.
9. Report changed files, completed functionality and any remaining limitations.

Do not implement the entire application in one step. Begin with the project foundation and proceed feature by feature.

**Primary objective:** Build a maintainable, secure and responsive Electronic Document Management System using Vue 3, shadcn-vue, NestJS, PostgreSQL, Redis and Tesseract OCR.
